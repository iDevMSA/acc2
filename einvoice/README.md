# الفوترة الإلكترونية (Cloud Functions — codebase `einvoice`)

خدمة سحابية توقّع الفواتير وترسلها إلى:

- **ZATCA (السعودية) المرحلة الثانية**: مفتاح secp256k1 وطلب شهادة، شهادة الامتثال برمز OTP، فحص المطابقة لكل أنواع المستندات، شهادة الإنتاج، ثم الإبلاغ عن الفواتير المبسطة (خلال 24 ساعة) واعتماد القياسية. عدّاد الفواتير (ICV) وسلسلة الـ hash (PIH) يُحفظان بقفل حتى لا يتكرر رقم.
- **ETA (مصر)**: بناء المستند بصيغة v1.0، التسلسل القانوني، توقيع CAdES-BES من ملف PFX، الإرسال، ومتابعة الحالة (Valid / Invalid).

## أين تُحفظ البيانات

| المسار | المحتوى | من يقرأ |
|---|---|---|
| `einvoiceVault/{uid}/zatca` | المفتاح الخاص، الشهادات، ICV و PIH | الخادم فقط (لا قواعد قراءة) |
| `einvoiceVault/{uid}/eta` | Client ID/Secret وشهادة PFX | الخادم فقط |
| `users/{uid}/einvoice/...` | بيانات المنشأة، الإعدادات، بيانات العملاء الضريبية، حالة كل مستند، الملف المرسل | المالك من الويب |

لا تكتب الخدمة في أي عقدة يكتبها تطبيق الهاتف؛ فواتير نقاط البيع تُقرأ فقط من `sales/{uid}/invoices`.

## النشر

يتطلب خطة Blaze (نفس شرط بوت واتساب):

```bash
cd einvoice && npm install
firebase deploy --only functions:einvoice
```

ثم من الويب: الفوترة الإلكترونية ← بيانات المنشأة ← الربط.

## الاختبار

```bash
npm test          # اختبارات التوقيع والحساب والتسجيل والإرسال بخادم وهمي
npm run build && npm run sandbox   # اختبار حقيقي مع بيئة ZATCA للمطورين (OTP 123345)، بلا Firebase
```

## ما تحتاجه من الجهات

- **ZATCA**: رمز OTP من بوابة فاتورة (fatoora.zatca.gov.sa) لكل وحدة إصدار. ابدأ ببيئة المحاكاة ثم الإنتاج.
- **ETA**: تسجيل نظام ERP في بوابة المنظومة للحصول على Client ID و Client Secret، وشهادة توقيع إلكتروني بصيغة PFX. شهادات الفلاشة (USB Token) لا يمكن استخدامها من السحابة.
